# §I — Acceptance Criteria

**Goal:** Gherkin for UI/E2E flows + INVEST for backend logic + perf bars + manual QA.

**Always asked.** No sprint locks without ACs.

## Discovery goals

1. Gherkin scenarios for UI/E2E (one per §F happy/error path)
2. INVEST criteria for backend logic (one per §D endpoint)
3. Performance bars (P95 latency, payload, query count)
4. Manual QA checklist

## Typical question shape

- I1 — **Gherkin scenarios**: "Based on §F happy path + error paths, I drafted these Given-When-Then scenarios: <auto-generated list>. Review and edit. Mark each with `complex: true` if it touches auth/RLS/payment/migration/JWT/secret/delete keywords (auto-flagged)."
- I2 — **INVEST criteria**: "For each §D endpoint, I drafted INVEST checklists: <prefilled>. Confirm each AC is Independent/Negotiable/Valuable/Estimable/Sized/Testable. Edit if needed."
- I3 — **Performance bars**: "<BRAND_PRODUCT_NAME> defaults: P95 < 800ms, payload < 50KB, ≤2 DB queries per request. Override per-AC or accept defaults?"
- I4 — **Manual QA**: "Generated checklist from §E pages + §F flows: <list>. Add edge cases or surface-specific items you'd want to manually verify before declaring done."

## Conditional follow-ups

- If I1 has >5 scenarios → propose splitting the sprint into 2
- If I2 has an AC where INVEST fails (e.g., not Independent) → push to refactor or split
- If I3 deviates from defaults → require justification (recorded for retro)
- Any AC flagged `complex: true` → auto-triggers pair-programming DRIVER mode in build phase

## Output flags

- `acs_total: <N>`
- `acs_complex: <count>` → triggers pair-mode count estimate
- `ac_split_warning: true/false` → if >5 ACs

## Complex AC auto-detection

Scan AC text for these keywords (case-insensitive):

- `auth`, `authentication`, `authorization`
- `payment`, `billing`, `charge`
- `RLS`, `row-level`, `policy`
- `migration`, `schema change`, `drop table`
- `JWT`, `token`
- `secret`, `credential`, `key`
- `delete` (especially "hard delete", "permanent delete")
- `password`, `hash`
- `encrypt`, `decrypt`

If 1+ keyword matched → set `complex: true`. Surface to user: "AC-N flagged complex (keywords: <list>). Will engage pair-mode during build."

## Style guidance

- Gherkin scenarios MUST have Given-When-Then structure, not free-form
- Each AC must be testable — push back on AC like "feels good" or "works well"
- <BRAND_PRODUCT_NAME> performance defaults rarely change; override is exception
- Manual QA must include cross-user RLS check + mobile 375px
