# AC-10 — Wizard §J worker_rigor question

**Verdict:** Production
**Methodology:** wizard section update + amend-spec wiring

## Changes shipped

1. **`.claude/skills/sprint-spec-wizard/sections/J-risks.md`** — new question J5:

   > "How strict should worker output enforcement be for this sprint? `lax` (default) or `strict`?"
   >
   > - `lax`: only audit + testgaps workers block verify
   > - `strict`: every fired worker output is a required artifact for its day's phase gate
   >   Output flag added: `worker_rigor: lax | strict`.

2. **`scripts/sprint-amend-spec.sh` (--lock)** — reads `spec.partial.json.sections_answers.J.worker_rigor`, validates against `lax|strict`, writes to `state.worker_rigor` via `atomic_update_state` before the advance-phase delegation.

## Behavior

```
Wizard §J5 collects:  worker_rigor ∈ {lax, strict}
  ↓ (stored in spec.partial.json.sections_answers.J.worker_rigor)

sprint-amend-spec.sh --lock:
  ↓ jq -r '.sections_answers.J.worker_rigor // "lax"' spec.partial.json
  ↓ atomic_update_state "$SLUG" '.worker_rigor = $r'

phase-predicates.sh:
  ↓ reads state.worker_rigor (default "lax" if unset)
  ↓ if worker_rigor == "strict":
       evaluates manifest.phases.verifying.strict_only_sub_step_gates[] too
       (verify-worker-map-refreshed, verify-worker-consolidate-refreshed)
  ↓ if worker_rigor == "lax": skips those
```

## Manifest integration (already in AC-1)

`phase-manifest.json:verifying.strict_only_sub_step_gates`:

```json
["verify-worker-map-refreshed", "verify-worker-consolidate-refreshed"]
```

Plus the `state-locked` phase manifest requires `worker_rigor ∈ [lax, strict]`:

```json
{
  "kind": "json_path_in",
  "path": "state.json",
  "json_path": ".worker_rigor",
  "in": ["lax", "strict"]
}
```

So `sprint-advance-phase.sh spec-locked` will REFUSE to advance unless worker_rigor is set. This forces the wizard §J question to be answered before the operator can move past spec-lock.

This sprint chose `lax` (set during AC-2 proof setup). Verified `check_phase_requirements spec-locked` passed with this value.

## What this proves

1. **Wizard question integrated** — §J5 added to the canonical question bank.
2. **Persistence path** — sprint-amend-spec.sh --lock writes the answer to state.json before advance-phase.sh runs.
3. **Phase gate enforcement** — spec-locked manifest predicate forces worker_rigor to be set before phase can advance to design-locked.
4. **Strict mode wiring** — phase-predicates.sh already reads worker_rigor and evaluates strict_only_sub_step_gates[] only when "strict".
5. **Default safety** — missing/invalid value defaults to "lax" (least restrictive); explicit "strict" opt-in.
