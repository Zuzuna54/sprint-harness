# §G — Visual Design & Brand

**Goal:** design system fit + typography/spacing/color + iconography.

**Skip if:** `sections_answers.A.no_ui == true`.

## Discovery goals

1. Existing shadcn/ui components used vs new tokens needed
2. Typography / spacing / color — follow Ordex brand book or deviate
3. Iconography — Lucide icons + any new ones needed

## Typical question shape

- G1 — **Design system**: "Based on §E components, these existing shadcn/ui components apply: <list scanned from `apps/web/components/ui/`>. Any new design tokens (colors, spacing, fonts) needed, or stay within existing system?"
- G2 — **Typography/color**: "Ordex brand book covers §12 (color), §13 (typography), §14 (icons), §15 (spacing), §16 (motion). Default: follow brand book exactly. Deviations needed for this sprint?"
- G3 — **Iconography**: "Based on §F flow steps, suggested Lucide icons: <auto-generated from verbs>. Add or modify?"

## Conditional follow-ups

- If G1 needs new tokens → require: "Does this break Ordex brand parity? If yes, surface to design review."
- If G2 deviates → require ADR mention in §J risks
- If G3 needs a non-Lucide icon → check `packages/ui/icons/` for custom icons first

## Output flags

- `new_design_tokens: true/false`
- `brand_deviation: true/false` → drives §J risk

## Recall targets

- `Ordex Planner design-parity locked decisions`
- Brand book references (from `docs/plans/desk_audit/`)

## Style guidance

- G is the shortest section — usually 2-3 questions max
- Default to brand parity; deviation is the exception, not the rule
- Icon naming: Lucide `<Verb>` or `<Noun>` PascalCase
