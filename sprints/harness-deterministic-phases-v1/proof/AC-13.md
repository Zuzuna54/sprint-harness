# AC-13 — --replay-gate-history validator

**Verdict:** Production
**Complex:** true (CI gate / replay validator)
**Methodology:** real-state run + injected-violation catch

## Artifacts shipped

1. `scripts/sprint-replay-validator.mjs` — standalone Node validator (235 lines).
2. `scripts/sprint-system-test.sh` — `--replay-gate-history` mode delegates to validator.

## Validator checks (4 assertions per closed sprint + 1 corpus-wide)

| Check                      | What it asserts                                                                                                                                                                                                                                                                                             |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| (a) gate_history monotonic | Each entry's `at` timestamp ≥ previous entry's. Catches out-of-order writes that would break replay-ordering inferences.                                                                                                                                                                                    |
| (b) Coverage               | For each `phase` walked through (collected from `gate_history[].from` + `.to`), every `manifest.phases[phase].required_sub_step_gates[]` is present in `state.gates_passed[]` ∪ `state.gates[]` ∪ `state.gate_bypasses[].gate`. Adds `strict_only_sub_step_gates[]` when `state.worker_rigor === "strict"`. |
| (c) Bypass validity        | Every `gate_bypasses[]` entry has `.gate` (a string), and if it looks like a sub-step name (no `/` or `.`), it must be in the manifest. `.why` must be ≥10 chars.                                                                                                                                           |
| (d) Doc-vs-manifest drift  | Every kebab-case gate name in `docs/sprints/USAGE.md`'s `## Phase enforcement` section must exist in `phase-manifest.json` (catches stale doc references).                                                                                                                                                  |

## Skip rules

- `--ignore-pre <ISO-date>` (default `2026-05-19T00:00:00Z`): skip sprints closed before this date.
- Implicit "pre-v0.7 closure" skip: if `gate_history[]` has no entry with `.by === "sprint-advance-phase.sh"` AND `state.worker_rigor === undefined`, skip. These sprints closed via the old inline-jq path and aren't subject to the new replay contract.

## CI wire (next commit, AC-14)

`.github/workflows/test.yml` will add a step:

```yaml
- name: replay validator
  run: bash scripts/sprint-system-test.sh --replay-gate-history
```

Default behavior: PR fails if any post-v0.7.0 closed sprint fails replay. `--ignore-pre` knob lets operators tighten over time.

## Delegation wire

`bash scripts/sprint-system-test.sh --replay-gate-history [<args>]` `exec`s `node scripts/sprint-replay-validator.mjs <args>`. All standalone validator flags pass through.

## What this proves

1. **Closed sprints have an audit trail** — every phase transition is recorded with from/to/at/by, and the chain replay assertion catches gaps.
2. **Bypasses are well-formed** — short or missing rationales fail replay.
3. **Doc drift caught** — gate names in USAGE.md that aren't in the manifest fail replay (prevents prose-vs-mechanism drift).
4. **Pre-v0.7 sprints skip gracefully** — operators can adopt incrementally; only post-enforcement closures are held to the new contract.
5. **Standalone tool** — replay-validator.mjs is invokable from CI, from sprint-system-test.sh, or directly. No infra coupling.
