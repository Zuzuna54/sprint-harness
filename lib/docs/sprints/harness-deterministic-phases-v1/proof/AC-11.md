# AC-11 — Day-5 sentinel headings enforcement

**Verdict:** Production
**Methodology:** inject-violation-catch-restore

## Changes shipped

1. `scripts/sprint-checkin.sh` generates `check-in-day5.md` with 3 H3 sentinel headings (`### Cut`, `### Push`, `### Pivot`) instead of inline bullets. Each section asks for ≥30 chars of operator content.
2. New `--validate` mode: parses `check-in-day5.md`, asserts each H3 has ≥30 non-placeholder chars under it, records `day-5-question-{cut,push,pivot}` sub-steps when valid. Returns exit 1 with `[FAIL]` lines per missing answer.
3. `day-5-hill-chart-refreshed` sub-step recorded automatically when the template is first generated.

## Phase-manifest predicates (already in AC-1)

```json
"day-5-checkin": {
  "required_artifacts": [
    { "kind": "file_contains_heading", "path": "check-in-day5.md", "heading": "### Cut",   "min_chars_under": 30 },
    { "kind": "file_contains_heading", "path": "check-in-day5.md", "heading": "### Push",  "min_chars_under": 30 },
    { "kind": "file_contains_heading", "path": "check-in-day5.md", "heading": "### Pivot", "min_chars_under": 30 }
  ],
  "required_sub_step_gates": [
    "day-5-question-cut",
    "day-5-question-push",
    "day-5-question-pivot",
    "day-5-hill-chart-refreshed"
  ]
}
```

So `sprint-advance-phase.sh building` (or `→ cleaning`, `→ verifying`) called from `day-5-checkin` phase will refuse to advance unless ALL 4 sub-steps recorded + all 3 sentinel-headings have content.

## Inject-violation-catch-restore

```
TEST 1 — Empty sentinels → FAIL
  $ cat > check-in-day5.md <<'EOF'
  # Day-5 check-in
  ### Cut
  ### Push
  ### Pivot
  EOF
  $ bash scripts/sprint-checkin.sh harness-deterministic-phases-v1 --validate
  [FAIL] day-5-question-cut: '### Cut' has 0 non-placeholder chars (need ≥30)
  [FAIL] day-5-question-push: '### Push' has 0 non-placeholder chars (need ≥30)
  [FAIL] day-5-question-pivot: '### Pivot' has 0 non-placeholder chars (need ≥30)
  [SUMMARY] day-5 validate: 3 question(s) need ≥30 chars under their H3 heading.
  RC=1
  ✓

TEST 2 — Italic-only placeholder body (gets stripped) → FAIL
  $ cat > check-in-day5.md <<'EOF'
  ### Cut
  _drop AC(s): list specific AC IDs and rationale_
  ### Push
  ### Pivot
  EOF
  $ bash scripts/sprint-checkin.sh --validate
  RC=1  (italic-only placeholder lines counted as 0 chars after grep -vE filter)
  ✓ (forces operator to write actual content, not just leave the template italic placeholders)

TEST 3 — ≥30 chars of real content → PASS + sub-steps recorded
  $ cat > check-in-day5.md <<'EOF'
  ### Cut
  No ACs to cut. All 14 are progressing — Wave 1+2 done, Wave 3+4 small.
  ### Push
  Keep scope. Wave 3+4 smaller than Wave 2; appetite cost manageable. Continue.
  ### Pivot
  No pivot needed. Architecture working: manifest + advance + predicates + sub-steps.
  EOF
  $ bash scripts/sprint-checkin.sh --validate
  [OK] day-5-question-cut: '### Cut' has 56 chars
  [OK] day-5-question-push: '### Push' has 66 chars
  [OK] day-5-question-pivot: '### Pivot' has 72 chars
  [OK] All 3 day-5 questions answered. Sub-steps recorded.
  RC=0
  state.gates_passed[]: day-5-question-cut, day-5-question-push, day-5-question-pivot all recorded
  ✓
```

## What this proves

1. **The 3 day-5 questions are mechanically enforced** — model cannot skip them and leave the sprint advance succeeding. `sprint-advance-phase.sh` will refuse without all 4 sub-steps.
2. **Italic-only placeholders DON'T count** — the grep -vE filter strips template `_(any blockers, surprises, course corrections)_` lines so operators can't trivially fake-fill with the template.
3. **Bash 3.2 compatible** — uses `tr 'A-Z' 'a-z'` (not `${var,,}`) for lowercase, `|| true` after grep -v for pipefail safety.
4. **awk-based heading scoping** — body extraction stops at the next H1-H3 heading, so content under `### Cut` doesn't bleed into `### Push`'s count.
