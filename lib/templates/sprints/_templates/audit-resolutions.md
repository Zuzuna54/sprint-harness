## How to use this file

1. **Operator invokes** `bash scripts/sprint-audit-resolve.sh --slug <slug>` (or auto-invoked on entry to `audit-resolution` phase).
2. **For each finding,** operator chooses: Fix / Defer / Accept.
   - **Fix:** make the code change, then `sprint-audit-rerun.sh` re-fires audit + diffs against baseline. On success, finding moves to FIXED with evidence.
   - **Defer:** REQUIRED to provide follow-up sprint slug + AC ID. Cannot defer without a named follow-up.
   - **Accept:** REQUIRED to provide risk owner + business rationale. Recorded for audit trail.
3. **Resume safe:** every decision is atomically persisted to `state.audit_findings_{resolved_count, deferred[], accepted[]}` immediately. Ctrl-C anytime; re-invoke `sprint-audit-resolve.sh` to pick up where you left off.
4. **Exit:** when `resolved + deferred + accepted == total`, the phase exit predicate passes, advance to `pre-deploy` succeeds.

## Security: rationale fields are PII-redacted

Per C5: every operator-typed rationale (defer.rationale + accept.business_rationale) is piped through `scripts/sprint-pii-redact.sh` before landing in `state.json` or this markdown file. Strips: emails, UUIDs, JWTs, API keys, password=…, postgres URLs. DO NOT paste secrets into rationale — they're filtered but should never originate there.

## Replay validator integration

The audit-resolution phase exit gate `audit-findings-exit-predicate` records to `state.gates_passed[]` only when the arithmetic holds. Replay validator (`scripts/sprint-replay-validator.mjs`) walks `audit_findings_*` state fields to confirm: every finding has exactly one of {resolved, deferred, accepted} status + no dangling deferrals.
